- **"Underwater" sound** = the raw band-passed feed sounds muffled. The raw side of the blend adds muffle; the NR slider is therefore the direct **muffle-vs-static trade** (100% = full engine output, 0% = pure band-pass = all static present)
- Approved at `1fe44c5`: 0% slider = static fully present, 100% = static completely gone, no underwater artifact
- **Rejected approaches — do not retry**:
  - Per-band spectral blend with noise-floor gating (built at `4d1509e`, reverted): left ≥50% raw in the voice bands at *every* slider position, so the muffle could not be removed at any setting
  - Crush-aware wet easing (prototyped, reverted): robotic/buzzy — the RNN's per-frame gain wobbles at syllable rate, so any per-frame-varying wet between two phase-different signals is a moving comb; and white noise constantly exceeds its own average floor, so the detector fired on static

## 6. Load-bearing technical details (re-stated in case AGENTS.md falls behind)

- RNNoise: 48 kHz, 480-sample (10 ms) frames; input samples must be in i16 range `[-32768, 32767]` (scale by 32768 around `process_frame`, scale back after); first frame discarded
- NR2: fft 512 / overlap 2 / hop 256 at 48 kHz; **must be called at exactly 256-sample hop cadence** (any other cadence corrupts its overlap-add); built-in **DELAY = 512 samples** (one FFT frame)
- Dual path: **both engines are fed every sample** (stays warm, instant switching); selection per block via `Arc<AtomicU8>`; each path has its own consumed index into the band-passed accumulator; only the selected engine's blended block reaches the ring; the first pushed block is discarded (NR2's ~2-hop OLA startup ramp + ~1 s dry→wet ramp, mirroring RNNoise's first-frame discard); switch gaps are filled with silence — provable worst case `2×FRAME + HOP` = 1216 samples ≈ 25 ms switching away from RNNoise (an earlier `< FRAME + HOP` bound caused a live panic; the fill is chunked with `saturating_sub` + `debug_assert`)
- The NR2 blend's raw side is delayed by 512 samples in an `nr_hist` ring to phase-align with the engine output; **while keyed the path pushes the current raw, no delay**
- TX→RX PTT edge → NR2 `resetTransient()` (discards the OLA ring, keeps the converged noise estimate, re-arms the ramp); RNNoise keeps processing while keyed (stays warm, no fade-in on key-up)
- Gamma table: 116,162 values (2×241×241), upstream SHA-256 `de43a4b9c7db4445997e6452852980d58d2558d635ab3c63e6423a347ba326c3`, integrity pinned by a Rust test (`[0]=0.725654181154077`, `[116161]=1.0`, max `19.119792331180907`)
- NR2 engine defaults: gainMax 1.0, gainFloor 0.0, qSpp 0.2, gainSmooth 0.85, gainMethod 2 (Gamma), npeMethod 0 (OSMS), aeFilter on, post2 off
- PTT: rigctld "default" protocol (no banner, no ACK), command `t\n` → `0` RX / `1` TX / `2` TX mic / `3` TX data / `255` disconnected; `RPRT` answer = keep last state; keyed (1–3) forces wet = 0; polled every 100 ms, reconnecting every 1 s while a target is set
- Output: linear-interpolation resample 48 kHz → device mix rate when they differ (safe: signal band-limited to 3 kHz); volume slider 0–300% (max gain 3.0 = +9.5 dB), post-gain samples clamped to ±1.0 (WASAPI float range) — loud peaks clip above 100%
- `BUFFER_FRAMES` = 960 (~20 ms) fixed shared-mode buffer on both streams — buffer depth is the heard echo latency
- Real-time rules: no allocations, no locks, no I/O, no `println!` in the audio callbacks; all DSP state is allocated on the GUI thread at Start and moved into the stream closures; callbacks talk to the GUI only via atomics and the lock-free SPSC ring
- Settings: `%APPDATA%\SSB Noise Filter\config.ini` — `filter=0|1`, rig host/port, connection state; auto-reconnect at startup if the app was connected when it last exited
